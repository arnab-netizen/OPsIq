# Owner Workload Evidence Ledger

Proves OpsIQ **removes** owner work rather than adding advisor homework. Numbers are the
actual `ownerWorkloadTransfer` (`OwnerWorkloadTransferScore`: minutesBefore/minutesAfter/
minutesSaved/pctReduced) computed by `composeWealthCommandCenter` from each Work Package's
`ownerWorkload` estimate, captured by running
`src/__tests__/owner-strategy/real-world-wealth.test.ts` on `main` (`1ef21e2`).

Every safe/blocked scenario produces a Work Package (`wp=yes`) and a proof requirement
(`proof=yes`); the owner's residual is a single decision (approve / acknowledge block),
not the full task. `nbm` = Next Best Move decision (BLOCKED = unsafe stopped;
CHOOSE_ALTERNATIVE = trap/owner-job redirected to a safer prepared action; DO_THIS = safe
action fully prepared).

**Aggregate:** 10/10 scenarios reduce owner workload; range 64–92%, mean ≈ **77%**. Owner
workload is **never increased**. Artifacts/tasks/proof generated by OpsIQ (not the owner):
each Work Package carries prepared artifacts, an assignee role, a proof requirement, and an
outcome-measurement window (`work-package.types.ts` — `artifacts`, `assigneeRole`,
`expectedOutcome`, `measurementWindowDays`); the owner's remaining work is the
`decisionStillRequired` field only.

Startup Mode workload transfer is modelled identically via
`startupValidation.validationWorkPackage.ownerWorkload` (minutesBefore/After) surfaced by
`composeWealthCommandCenter` in startup mode (`command-center.ts:92-95`); all 10 startup
scenarios (`real-world-startup.test.ts`) produce a validation Work Package with kill/pivot
criteria and `launchAllowed=false` before validation, so the owner never carries the full
launch-planning burden.
