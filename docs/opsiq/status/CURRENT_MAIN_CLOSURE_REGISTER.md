This is real operational evidence that the recurrence/safety gate added in PR #358 works as designed — produced by an actual human data-entry error in live use, not a synthetic test scenario.

## Cross-domain owner-action dashboard ordering (PR #361)

| Item | Status | Evidence |
|---|---|---|
| Assign-lifecycle non-determinism (Sales/Operations/Strategy/Cashflow/Marketing/Finance/SOP) | CLOSED, PRODUCTION_PROVEN, RECURRENCE_GATE_ENFORCED | PR #361, merged. Root cause: `dashboard.service.ts` in all 7 domains ordered owner actions by a single key (`priorityScore desc`); `calculateOwnerPriorityScore`'s hard ceiling (`Math.min(100, ...)`) means multiple critical findings routinely tie at exactly 100, and Postgres does not guarantee stable order across ties on a non-unique key — so the dashboard's "top action" could reorder between a page load and the very next read. This is exactly what caused Live Production Owner Acceptance's Assign-lifecycle tests to fail in 5 domains (the UI clicked the position it read as "top," but the assigned action appeared to still be `proposed` on the next read). Fixed with a deterministic 6-key total order (`priorityScore desc, expectedImpactScore desc, confidence desc, findingCode asc, title asc, id asc`, the last key being a new SQL-layer-only tiebreaker since every persisted row has a unique non-null `id`) in all 7 files; `founder-recovery/dashboard.service.ts` (`createdAt asc`, a naturally-ordered column) confirmed NOT part of this defect class and left untouched. Recurrence gate: `owner-action-dashboard-ordering-governance.test.ts` (30/30 passing) statically asserts the exact 6-key sequence in all 7 files and that the old single-key form is gone; a real-Postgres hostile test (`owner-action-ordering-determinism.db.test.ts`) seeds actions tied on every ranking field and proves repeated reads are byte-identical. Production proof: live run `33082554130` — every domain's Assign→Start→Complete→Verify lifecycle test (Finance 01-07, Sales 21-06, Operations 22-06, Strategy 23-06, Cashflow 24-09, Marketing 25-06, Recovery 26-06) passed against real production data. |
